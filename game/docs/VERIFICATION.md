# Forest Trail 验证报告（第二版）

**结论：**第二版的全部新增内容都在真实浏览器里实测过：
- 三辆可选车辆；
- 车灯（近光 / 远光）与昼夜；
- 颠簸路面与四个新区域；
- 训练场计时；
- 背景音乐和新界面；
- 一键录制演示与封面生成。

无头物理回归覆盖三辆车：试验场 D01–D12 每辆 15/15 通过；整圈、训练场全程、峡谷含吊桥都能无复位跑完。三辆车的悬挂在 9 种极限姿态下都没有穿模。实测 6 个典型场景都稳定在 60 fps（垂直同步上限），包括开远光的夜间密林。`npm install`、`npm run dev`、`npm run build` 均已执行成功。

## 1. 环境与方法

| 项目 | 内容 |
| --- | --- |
| 浏览器 | Playwright 驱动的 Chromium，WebGL2 走 ANGLE，GPU 为 NVIDIA L4 |
| 窗口 | 1440×900（截图、性能），1920×1080（演示录制），像素比 1 |
| Node / Blender | Node 22.23.1 / Blender 4.5.12 LTS |
| 构建 | tsc 零错误；JS 包 5.37 MB（gzip 1.77 MB）；`dist/` 共 28 MB，其中音乐 14 MB、模型 6.3 MB |

验证分四层：

1. **资产层：**`npm run assets` 从脚本完整重建所有模型（18 秒），并对三辆车做自动穿模检测。
2. **无头物理：**Node 里运行与游戏相同的代码和世界。
   - `tools/proving.ts <车辆>`：D01–D12 试验场。
   - `tools/sim-test.ts`：整圈、训练场、峡谷和专项测试，用 `VEH=<车辆>` 选车，用 `FULL=1` 加载全部静态碰撞体。
3. **浏览器脚本：**通过调试接口 `window.__ft` 传送、自动驾驶、控制机位，读取游戏状态并截图目视检查。
4. **真实输入：**用 Playwright 的真实鼠标点击和键盘事件走一遍界面和按键。

### 4.2 玩法

- **训练场计时（自动驾驶 TOYOTA 实跑一圈）：**
  - 穿过拱门后提示“计时开始”；
  - 7 对旗门依次触发，分段时间分别为 0:32.6、1:19.4、1:53.4、2:12.9、2:41.7、2:53.8、3:09.0；
  - 3:21.9 回到拱门停表，提示“新纪录”，最佳成绩写入存档。
- **探索点：**在训练场、船屋附近停稳后出现“按 F 记录「越野训练场」/「湖畔船屋」”。记录后计入“探索点 n/4”，不改变主线进度。
- **吊桥：**把车传送到桥面，车身停在 26.31 m，桥面 25.91 m，沟底 19.6 m，四个车轮都压在桥面碰撞体上。复位和读档用的是同一个传送函数。
- **换车：**游戏中在暂停菜单换车，车辆在原地重建，绞盘先断开，车灯和泥污照常工作。

### 4.3 演示录制与封面

- **一键录制：**在 1920×1080 窗口点击“录制演示视频”，运行约 127 秒（含点击和导出）后自动下载 WebM，133 MB，录制期间平均 56 fps。这是修复天空接缝、昼夜过渡和夜间亮度之后的第四次录制。
  - 视频为 VP9 1920×1080，7530 帧 / 126.2 秒（≈ 60 fps）；音频为 Opus。
  - 抽帧检查：遮幅黑边、字幕卡、开场和结尾标题、淡入淡出都在视频里；夜间车灯和营地镜头不再出现黑色点状弧线；“昼夜交替”镜头逐秒抽帧，从黄金时刻到深夜是渐变的，天空没有接缝。
  - 转码后得到 `docs/demo.mp4`：1080p 30 fps H.264，实测响度 -15.8 LUFS，61 MB。
- **观看演示：**不录制时逐镜头截图检查了 14 个镜头，全程 60 fps，结束后车辆、时段、位置都恢复原状。
- **封面：**点击“生成封面”下载 1200×1800 PNG，即 `docs/cover.png`。

### 4.4 音乐

标题、白天、夜晚、演示四组歌单在对应场景下的播放曲目都已读到（见 4.1）。曲目切换使用交叉淡入淡出。录像音轨的响度是 -26.7 dB（平均），说明游戏音频确实进入了录制流。实际音色和混音平衡只能靠文件本身判断，本环境无法试听。

## 5. 性能

测量方式：每个场景稳定 2.5 秒后，连续采样 300 帧（requestAnimationFrame 间隔），画质为“高”，行驶场景由自动驾驶驱动。

| 场景 | 帧率 | 帧时间 p95 | 绘制调用 | 三角面（含阴影） |
| --- | --- | --- | --- | --- |
| 白天密林行驶 | 60.1 | 16.8 ms | 2036 | 1260 万 |
| 夜间密林 + 远光（带阴影聚光灯） | 60.1 | 16.8 ms | 2297 | 1440 万 |
| 越野训练场 | 60.1 | 16.7 ms | 2184 | 920 万 |
| 赤岩峡谷 | 60.1 | 16.8 ms | 1694 | 1030 万 |
| 夜间营地（篝火、串灯、提灯） | 60.1 | 16.8 ms | 2371 | 1400 万 |
| 东侧秋色林 | 60.2 | 16.7 ms | 2211 | 980 万 |

**限制：**帧率被垂直同步限制在 60，表中只能证明“没有掉帧”，看不出还剩多少余量。L4 是数据中心 GPU，笔记本核显上的表现没有实测，低画质预设就是为此准备的。

### 5.1 初次 SSAO 条纹修复补测（2026-09-25，31686b4 历史记录）

车底、草根附近的规则细条纹来自半分辨率、10 次采样的 SSAO。修复后高 / 中画质分别使用 24 / 16 次采样，AO 缓冲与实际渲染画布同尺寸；强度 0.4、半径参数 1、power 2，保留深度感知模糊和固定采样。低画质关闭 AO。

在生产构建上固定世界、机位、太阳阴影和曝光，仅切换旧 / 新 SSAO 参数，目视对比车轮、草根、松林、秋色小屋和夜间营地。已复现的条纹明显减弱，接触阴影保留，暗部没有因增加采样而变成大片黑色。[修复前后对照](screenshots/ssao-fix/comparison.png)、[原始修复前图](screenshots/ssao-fix/contact-before.png)、[原始修复后图](screenshots/ssao-fix/contact-after.png)、[配置、源码哈希与实测记录](screenshots/ssao-fix/verification.json)。

画质按高 → 中 → 低 → 高切换，检查了 AO 纹理实际尺寸、低画质 AO 通道销毁和 WebGL 错误；恢复高画质后，同一静止场景的 PNG 哈希完全一致。白天与夜间远光的自动驾驶检查均实际行驶超过 12 m。运行期间没有页面、资源请求或 WebGL 错误；`npm run build` 通过。

### 5.2 明暗层次回归修正（2026-09-25）

### 5.3 扬尘发黑修复（2026-09-26）

行驶粒子使用受光材质，却设置了 `useSkybox = false`；场景的恒定环境光为零，补光来自天空环境贴图，因此扬尘在夜间缺少补光，重叠后形成黑团。粒子材质现在开启 `useSkybox`，接收场景已有的环境光；镜面反射为零，自发光颜色也为零，保留正常受光和透明混合。

生产构建中实测了白天扬尘、夜间远光扬尘、泥地甩泥和浅滩溅水。分别确认 56、60、24、32 个活跃粒子，并从实际接地车轮读取地表与水深；甩泥场景四轮均在泥地，溅水场景四轮水深约 0.10–0.27 m。固定每个场景的粒子、机位和光照，仅切换材质环境补光，目视检查尘雾、泥点和水花的颜色与透明度；夜间尘雾恢复环境光颜色，原先的黑团消除。

`npm run build` 通过，四个场景没有浏览器、资源请求或 WebGL 错误。[白天 / 夜间对照](screenshots/dust-lighting/comparison.png) · [源码哈希、材质状态及验证记录](screenshots/dust-lighting/verification.json)。

| 夜晚第一次调参后太亮，像黄昏 | 月光和夜间环境光倍数下调 |
| 下调后夜晚又太黑，只剩车灯和营地灯光照到的地方；白桦、白杨树干在月光下像在发光 | 月光 0.6→0.85、环境光 2.6→3.4、曝光 1.35→1.45；树皮顶点色从接近白色降到约 0.47 的真实反照率（引擎把顶点色当线性值读，原值实际约 0.7） |
| 视频里天空云层有几条直线接缝：云噪声的 `fract(p * 233.34)` 哈希在相邻格子对同一角点算出不同值 | 云层、瀑布、地面噪声统一换成只做精确小整数运算的 mod-289 哈希；把云染暗后复查，接缝消失 |
| 昼夜过渡在蓝调时刻中段“一下子变黑”：环境光在 4 份预生成贴图之间硬切，方向光同时从落日换到月亮，线性插值又让画面一直偏亮到最后 | 环境光改为 13 份预生成加亮度连续缩放；日月交接时光强、光盘和光晕淡出再淡入；颜色和光强按对数插值；N 键过渡 4→8 秒，演示里 9.5→12.5 秒 |
| 车漆饱和度偏高，在 ACES 和调色后显得像塑料 | 车身色饱和度降到原设计的约 65%，色卡同步 |
| 标题页淡入动画结束时写入 `transform: none`，覆盖面板的居中定位，底部按钮被截断 | 淡入只改透明度 |
| 标题页镜头会把车转到左侧面板后面 | 标题页专用环绕机位，车始终在两个面板之间 |
| 录制的视频没有字幕和遮幅：`captureStream` 只录 WebGL 画布 | 录制时逐帧合成到 2D 画布再录 |
| 录像音量偏低（平均 -32.8 dB） | 录制支路 +6 dB 加限幅器；MP4 再做 -16 LUFS 归一化 |
| 传送到桥上的车掉进干沟 | 新增行驶面高度（桥面优先），传送、复位、读档都用它 |
| 演示镜头：机位钻进地形、被树冠或沟壁挡住、车出画 | 逐镜头截图检查三轮，机位改为相对地形抬高并钳制在地面以上 |

## 7. 剩余限制

- **手柄：**新增的车灯按键（十字键上、右）和原有映射一样，只按标准映射实现，没有实体手柄实测。
- **音频：**音乐、虫鸣和猫头鹰只验证了播放状态和录像音轨电平，没有人耳试听。
- **地形分辨率：**弹坑和交叉轴建在 1 m 地形网格上，边缘偏圆润；近看不如建模件锐利。
- **演示：**演示没有展示绞盘。镜头按当前地图坐标编排，如果以后改地图，需要重新检查镜头。
- **视频：**游戏内录制的 WebM 没有时长元数据（MediaRecorder 的通病），部分播放器拖动进度条不便。交付的 MP4 已经重新封装。
- **评估方式：**手感和美术效果由开发者对照规格、参考图和截图判断，没有第三方玩家试玩。
